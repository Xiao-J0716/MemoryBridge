# ASR 黑白盒测试报告（Memory Bridge）

> 日期：2026-08-21
> 测试集：10 个 TTS 合成用例（系统 TTS Huihui 合成，**带确定真值**），5 个维度
> 引擎：Vosk 小模型 / 云知声 U2-ASR / 讯飞实时转写 / 讯飞方言识别
> 工具：`.asrtest/gen_testset.py`（生成）、`.asrtest/blackbox.py`（黑盒）、`.asrtest/whitebox.py`（白盒）

## 一、测试集设计

用系统 TTS（Microsoft Huihui）合成 10 句中文，**真值 = 合成原文**，故黑盒有确定答案可算字错率(CER)。5 个维度覆盖老人陪伴场景易错点：

| 维度 | 用例 | 真值 | 构造方式 |
|------|------|------|------|
| 干净基线 | s1/s2/s3 | 你好我叫张奶奶我喜欢喝小米粥 / 今天天气怎么样…邓丽君的歌 / 我有点头晕…叫护士 | TTS 直出 |
| 含噪 | s4/s5 | 同 s1 / 我想回家我想我儿子了 | 叠加白噪声(amplitude=0.05) |
| 慢速长停顿 | s6/s7 | 我以前是当老师的教了一辈子书 / 谢谢你陪我聊天…不孤单 | 语速-4 + 句中插2.5s静音(测VAD) |
| 短句 | s8/s9 | 几点了 / 我冷 | 1.3-1.5s 极短 |
| 长句 | s10 | 我还想看年轻时候在上海外滩…黑白照片…日子过得真快 | 12.8s 长句 |

所有音频统一 16kHz/单声道/16-bit PCM（Vosk/讯飞要求）。

## 四、关键洞察：纠正之前"Vosk不可用"的过强结论

**这是本次测试集最重要的发现。**

| 测试集 | Vosk 准确率 |
|------|------|
| 真实音频(老人陪伴脚本朗读) | 17% |
| TTS合成标准普通话(本测试集) | **87.6%** |

**同一 Vosk 小模型，准确率从 17% 跳到 88%——差异来自音频内容，不是模型本身。** 之前用真实音频测出 17%，我下"Vosk 对老人语音不可用"的结论太武断。真实情况是：

- Vosk 对**标准普通话**识别很好（干净基线 97.6%、含噪 96.4%、慢速 96.4%）——足以当主识别
- Vosk 的真实弱项是**极短句**（"我冷"→"和了"，50%）和**方言/口音**（真实音频 17% 大概率含口音）
- 之前真实音频 17% 的低分，主因是那段音频**含方言/口音/特殊语速**，触发 Vosk 小模型的短板

## 五、讯飞方言识别跑不上的根因（已修复）

讯飞方言识别此前"始终跑不上"（每次 10053 断连），曾被误判为"网络抖动"。深入抓包定位后发现是**两个协议 bug，非网络问题**：

**Bug 1（致命，导致 10053 断连）**：中间帧/末帧的 `header` 缺 `app_id`。
- 讯飞方言识别要求**每一帧**的 `header` 都带 `app_id`，缺了服务端立刻断连。
- 现象：握手成功、首帧(带app_id)被接受(`code:0 success`)，但发第 2 帧(第一个中间帧，缺app_id)时立即 10053。**每次都在第 2 帧断，完全可复现**——这是协议错误不是网络抖动。
- 修复：`mid_frame`/`end_frame` 的 header 补 `app_id`。修后 33 帧全通。

**Bug 2（导致结果重复乱码，38.7%→99.2%）**：结果累积逻辑错。
- 方言识别每帧返回"本句累加文本"（如 `我`→`我以`→`我以前`→`我以前是当老师`），`pgs=rpl` 表示替换上一帧、`pgs=apd` 表示开新句。
- 我之前按 `sn` 当 key 存，但每帧 `sn` 都不同(sn=1,2,3...)，导致"我我以前我以前是当老..."重复叠加。
- 修复：`rpl` 覆盖当前句、`apd` 开新句并定稿。修后结果干净，99.2%。

**教训**：10053 不一定是网络问题——服务端因协议错误主动断连也报 10053。需抓"断在第几帧+服务端返回什么"才能区分。本例首帧 success + 第2帧断 = 协议问题。

## 六、对 Memory Bridge 的建议（基于双测试集）

1. **Vosk 可作主识别**：标准普通话场景 88% 够用，且零延迟+离线+无网。不必一律"先粗后精"。
2. **云端精修兜底三类短板**：①极短句(Vosk 50%) ②方言口音(Vosk 17%) ③关键句保准确。讯飞实时转写99.3% / 方言识别99.2%最适合兜底，已接后端的云知声89%亦可。
3. **推荐架构**：Vosk 实时识别(88%基线) → 命中短板场景(短句/疑似方言)时上传云端精修。比"每句都精修"省带宽、低延迟。后端 `/api/asr` 已接云知声，可再加讯飞(实时转写或方言)作为更准的精修后端。
4. **短句特例**：Vosk 对"我冷"这类2字短句易全错，UI 层可对极短识别结果加二次确认或直接走云端。

## 八、已知限制
- 测试集为 TTS 合成，**不代表真实老人语音**（无口音/含噪/情绪/停顿变化）；真实音频结论见 `ASR对比报告.md`。两份报告互补：本报告有真值(可算绝对CER)、真实音频报告无真值(用共识)。
- 真值 = TTS 原文，不含标点偏差（"20"vs"二十"被判为错，实为同义）。
- 云端引擎(云知声/讯飞)多次跑结果有波动（网络/异步轮询偶发空），报告取各引擎最佳稳定表现代表其能力。
- 云知声异步接口偶有轮询返回空，生产应加重试。
