# ASR 引擎对比报告（Memory Bridge 老人陪伴场景）

> 日期：2026-08-21｜测试音频：4 段老人陪伴脚本朗读 m4a（`示例一/二`、`中科创达智能汽车产业园 ×2`）
> 方法：因客户端是老人实时说话、无"原文脚本"，故不用字面还原度，改用**多引擎共识 + 语义可用性**评估。
> 工具：`.asrtest/compare.py`（共识/可用性）+ `recognize.py`(Vosk) + 云知声 `transcribe_audio.py` + `ifly_rtasr.py`(讯飞实时转写)

## 三、共识与差异（高可信事实，无需原文）

**两云端引擎一致识别出的"老人真实意图"**（= 真实说出的内容，可信度高）：
- 报日期/天气（2026年8月7号、33度）
- 想听邓丽君的歌、想听儿歌
- 想看年轻时在上海外滩拍的黑白照片/老照片
- 有点闷、想回家、想回老窝
- 老家门口有棵大梧桐树、秋天妈妈在树下（摘/织/捉迷藏）
- 想听关于老槐树/老外族的故事
- 想打开"往事收容所"（万师手账书/万事收藏所）

**两引擎字面差异**（同音/近音不同字，非绝对对错）：
- 往事收容所 vs 万事收藏所 vs 万师手账书
- 老槐树 vs 老外族 vs 芦荟树
- 我感到有点闷 vs 我讲脑子有点懵
- 这些差异需人工或上下文判定，但**不影响下游 LLM 提取意图**。

## 五、给 Memory Bridge 架构的建议

1. **Vosk 不宜单独作为最终识别**：对老人真实语音一致性仅 ~32%、可用 0/4。但它**零延迟+离线+无网**仍有价值——保留为"先粗"快速反馈。
2. **必须接云端精修**：云知声或讯飞实时转写都能把 Vosk 乱拼提升到可用。推荐 **云知声为主**（异步但带时间戳+标点、质量最稳），**讯飞实时转写为备/低延迟流式**（近实时，适合边说边出字）。
3. **已落地**：后端 `server/services/asr_service.py` 新增 `UnisoundService`，`config.py` 加 `UNISOUND_API_KEY`，`.env` 切 `ASR_BACKEND=unisound`。已验证：客户端 Vosk 出粗结果 → 句末上传音频 → 后端 `/api/asr` 调云知声精修 → `AsrResult.Refined` 替换粗结果。**先粗后精链路已打通**（示例一.wav 经后端云知声识别出完整文本）。
4. **讯飞方言识别**逻辑已通（示例一出过正确结果："今天是2026年8月7号…邓丽君的歌…老槐树的故事"），但本机到 `iat.cn-huabei-1.xf-yun.com` 的 WSS 连接抖动（10053/10054），多次重试不稳定。脚本 `ifly_dialect.py` 保留，网络稳定后可补全对比；方言口音老人场景它可能比标准普通话引擎更准，值得继续。

## 六、复现

```bash
cd app
# 1) 转 4 个 m4a → 16k mono wav
for f in 示例一 示例二 中科创达智能汽车产业园 "中科创达智能汽车产业园 2"; do
  ffmpeg -y -i "Downloads/${f}.m4a" -ar 16000 -ac 1 -c:a pcm_s16le ".asrtest/audio_${f// /_}.wav"
done
# 2) Vosk（需模型在纯英文路径，见 C:/voskrun）
.asrtest/.venv/Scripts/python.exe .asrtest/recognize.py <wav> C:/voskrun/model
# 3) 云知声
python 云知声/skills/u2-asr-pro/scripts/transcribe_audio.py <m4a> --language zh-CN --env-file 云知声/skills/u2-asr-pro/.env.local
# 4) 讯飞实时转写
.asrtest/.venv/Scripts/python.exe .asrtest/ifly_rtasr.py <wav>
# 5) 对比
.asrtest/.venv/Scripts/python.exe .asrtest/compare.py
```

## 七、已知限制
- 无人工原文真值，准确率为"相对参照/共识"非绝对值。
- 云知声为异步接口，延迟高于讯飞流式。
- 讯飞方言识别协议已调通（首帧带音频、连续发完再收、按 sn 去重），示例一成功出过正确结果；但本机到讯飞 iat 域名 WSS 抖动（10053/10054），批量重试不稳定，仅示例一存档成功。
- 测试音频为清晰朗读，真实老人含噪/方言/停顿场景准确率会进一步下降——这正是离线 Vosk 更不可用、云端精修更必要的理由。
